# Regras de negócio

Registro de todas as regras que o app aplica. Cada regra aponta para onde está implementada e testada. **Regra nova ou alterada entra aqui na mesma tarefa** (ver `CLAUDE.md`).

## Convenções de sprint e versões

| Regra                                                                                                                                                                                                                                        | Onde                                     |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| Versão `X.Y` é sprint; `X.Y.Z` é correção na branch da qualidade (staging) da sprint `X.Y`; outros nomes são agrupadores. Os padrões são regex configuráveis.                                                                                | `domain/sprint/sprint-classifier.ts`     |
| Status fechado é o que o Redmine marca como fechado (`is_closed`); status como "Resolvida" ou "Em teste" podem continuar abertos.                                                                                                            | Redmine (lido de `/issue_statuses.json`) |
| Datas da sprint vêm de campos personalizados da versão, detectados pelo nome: `limite\|dev` = prazo dos devs; `publica\|lança\|release\|deploy` = publicação. Sem campo de publicação, vale a data da versão.                                | `detectDateFields`                       |
| A correção é reconhecida só pelo nome (`X.Y.Z` por padrão, regex em Configurações → Sprints e Início). Campos personalizados da versão (ex.: um sim/não de "vai para a branch principal") ainda não entram na regra (decisão de 2026-10-26). | `sprintKind` (`sprint-classifier.ts`)    |

## Sprints

| Regra                                                                                                                                                                                                                                                                            | Onde                                |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |

| **Em homologação**: aberta, prazo dos devs vencido, publicação no futuro.                                                                                                                                                                                                        | `classifySprints`                   |

| **Planejada**: demais sprints abertas.                                                                                                                                                                                                                                           | `classifySprints`                   |
| **Em produção**: a última sprint fechada já publicada.                                                                                                                                                                                                                           | `classifySprints`                   |
| **Correção**: versão `X.Y.Z` aberta; a sprint de origem é `X.Y`.                                                                                                                                                                                                                 | `classifySprints`                   |
| Quadro de sprint automática segue a fase escolhida (desenvolvimento, homologação ou correção) e troca sozinho de versão.                                                                                                                                                         | `pickSprint`, `BoardFilterResolver` |
| Versões ordenadas numericamente: 3.9 < 3.10 < 3.10.1.                                                                                                                                                                                                                            | `compareVersions`                   |
| **Início estimado** da sprint: dia seguinte ao prazo dos devs da sprint anterior (por número de versão). O Redmine não tem data de início de versão. Sem sprint anterior com prazo, não há início.                                                                               | `assignDevStarts`                   |

| **Entraram depois do início** = tarefas com data de criação depois do início estimado. **Fechadas nos últimos 7 dias** usa `closed_on`.                                                                                                                                          | `sprintProgress`                    |

## Início (fila de trabalho)

| Regra                                                                                                                                         | Onde                      |
| --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| **Parada**: sem atualização há N dias (padrão 5, configurável) **ou** com status que contém pausa/bloque/aguard/impedi (ou pause/block/wait). | `domain/redmine/queue.ts` |
| **Atrasada**: data prevista no passado e tarefa não fechada.                                                                                  | `isOverdue`               |
| **Prioridade alta** (indicador): tarefas da fila com prioridade alta, urgente ou imediata.                                                    | `isHighPriority`          |
| **Prazos**: vencidas ou vencendo nos próximos 7 dias.                                                                                         | `analyzeQueue`            |

## Horas

| Regra                                                                                                                                                                                                                                                                              | Onde                                                            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Horas digitadas como `1,5`, `1.5`, `2h`, `1:30`, `1h30`, `1h 30m`, `90m` ou `20 min`; o resultado tem duas casas (20 min = 0,33 h). Texto que não é duração é recusado.                                                                                                            | `parseHours`                                                    |
| Lançamento: mais de 0 e até 24 h, data real (qualquer data, passada ou futura), comentário obrigatório e uma tarefa. Arredondamento livre.                                                                                                                                         | `assertValidDraft`                                              |
| Atividade (tipo de trabalho do Redmine, não a tarefa): a última usada neste computador; senão a padrão do Redmine; senão a primeira. Inativas não aparecem; com uma só, o campo some.                                                                                              | `defaultActivityId`, `ReferenceDataQueries.timeActivities`      |
| Só os próprios lançamentos podem ser editados ou excluídos pelo app.                                                                                                                                                                                                               | `TimeEntryRow`                                                  |
| Cronômetro: um por vez; começar outro descarta o anterior, depois de confirmar. Guarda só instantes (início, pausas), então sobrevive a reiniciar o app.                                                                                                                           | `TimerService`, `startTimer`                                    |
| Pausa sozinho quando o computador dorme ou a tela é bloqueada. Depois de 10 min sem teclado e mouse (verificado a cada minuto), pausa a partir do momento em que a pessoa saiu: esse tempo não conta.                                                                              | `TimerService.onSleep`, `checkIdle`, `IDLE_LIMIT_SECONDS`       |
| Parar = pausar e abrir o lançamento com o tempo contado (duas casas, no mínimo 0,01 h, porque o Redmine recusa 0). O cronômetro só some quando o tempo é lançado ou descartado.                                                                                                    | `TimerService.stop`, `elapsedHours`                             |
| Semana de "Minhas horas" começa no dia configurado na Agenda; linhas por tarefa, da que tem mais horas para a que tem menos.                                                                                                                                                       | `weekDays`, `buildTimesheet`                                    |
| "Repetir semana passada": os lançamentos com tarefa da semana anterior, de novo 7 dias depois (mesma tarefa, horas, atividade e comentário), um por um; não verifica se já foram repetidos.                                                                                        | `RepeatWeekUseCase`, `shiftedEntries`                           |
| Pedido de lançamentos por período: o Redmine compara `spent_on` com `from`/`to` deslocados pelo fuso do usuário (a oeste de UTC perdia o primeiro dia, como a segunda de "Esta semana", e trazia o dia seguinte). O app pede um dia a mais de cada lado e corta no período pedido. | `listTimeEntries` (`http-redmine-gateway.ts`)                   |
| Resumo da aba Horas: horas por pessoa × atividade, atividades e pessoas com mais horas primeiro, com totais (aparece com 2+ lançamentos).                                                                                                                                          | `hoursByPersonAndActivity` (`domain/time/team.ts`)              |
| Cronômetro: ao iniciar, a tarefa vai para a situação configurada (`timerStartStatusId`), só se for diferente da atual e estiver entre as permitidas pelo fluxo; senão avisa.                                                                                                       | `useStatusOnTimerStart` (`IssueQuickActions.tsx`)               |
| Lançar horas (novo lançamento) pode mudar situação e responsável; começam com os atuais, que não mudam nada. Depois do lançamento vai só o que difere (`bulkDiff`); o que o Redmine ignorar vira aviso.                                                                            | `TimeEntryDialog` (`useIssueChange`), `CommentAndChangeUseCase` |

## Abas

| Regra                                                                                                                                                                                                    | Onde                                        |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| Cada tela tem uma aba só, e cada quadro tem a sua. Abrir uma tela já aberta traz a aba para a frente; a data da agenda ou a seção das configurações trocam dentro da mesma aba. Aba nova vai para o fim. | `openTab`, `tabKey`                         |
| "Quadros" sem quadro escolhido é o primeiro quadro, para não abrir duas abas do mesmo quadro.                                                                                                            | `withBoard`                                 |
| Fechar a aba da frente mostra a seguinte; se era a última, a anterior. Fechar todas deixa a área vazia com um aviso.                                                                                     | `closeTab`                                  |
| Ctrl+Tab / Ctrl+Shift+Tab andam em círculo; ⌘/Ctrl+1…8 vão para a aba da posição e 9 para a última, como nos navegadores.                                                                                | `stepTab`, `tabAt`, `useTabShortcuts`       |
| Quadro excluído perde a aba; se ela estava na frente, aparece a primeira.                                                                                                                                | `keepTabs`                                  |
| Aba escondida continua montada (guarda filtros, rolagem e formulários), mas não responde ao teclado: os atalhos da Agenda só valem com a aba dela na frente.                                             | `TabPanel`, `useIsActiveTab`                |
| Ao iniciar, as abas da última vez voltam (configurável); a agenda volta em hoje, não na data em que estava. Sem abas (configurável), cada navegação troca a única tela, como antes.                      | `loadTabs`, `routePath`, `useWorkspaceTabs` |

| Duplicar abre outra aba da mesma tela (`<tela>#2`…); o menu continua trazendo a primeira. ⌘/Ctrl-clique ou clique do meio no menu abrem sempre uma aba nova. | `openNewTab`, `NavItem` |
| Arrastar uma aba sobre outra a coloca no lugar dela; "Fechar as outras" deixa só a escolhida. Abas reabertas guardam a posição da aba da frente. | `moveTab`, `closeOtherTabs`, `saveTabs` |
| Cada aba tem a sua pilha de tarefas abertas no modal; abrir a tarefa que já está no topo não empilha de novo. Trocar de aba esconde o modal e voltar mostra o mesmo. Fechar a aba descarta o modal; Duplicar copia a tela sem ele. | `pushIssue`, `popIssue`, `TabIssueModals` |
| Tarefa aberta de fora das telas (barra lateral, busca, cronômetro, notificação do sistema) vai para a aba da frente; sem nenhuma aba, abre uma do Início. | `openIssueInFrontTab` |
| Os diálogos de uma aba cobrem só a área dela (barra de abas e lateral continuam clicáveis); Esc e os atalhos da Agenda ignoram diálogos de abas escondidas. O ⌘N usa os padrões (projeto, sprint) da tela da aba da frente. | `TabPanel`, `Dialog`, `useFrontTabNewIssue` |
| As pilhas de tarefas abertas são salvas com as abas e reabrem ao iniciar (só ids inteiros positivos; abas salvas antes disso abrem sem modal). | `saveTabs`, `loadTabs` |

## Trâmites (automações)

| Regra                                                                                                                                                                                                                                                                                                                                                                         | Onde                                                                                                            |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Um botão por regra, na ordem configurada, só nas tarefas dos tipos e situações escolhidos (nenhum = todos). "Novo trâmite" aparece sempre (na própria tarefa, com horas e tarefas ligadas).                                                                                                                                                                                   | `rulesFor`, `NEW_TRAMITE_RULE`, `HandoffButtons`                                                                |
| Regra salva com nome obrigatório; modelos vazios de "enviar" voltam ao padrão (`* Trâmite de {{tipoAtividadeComentario}}: {{noteSelecionado}}`); fechamento incompleto é descartado; até 30 regras.                                                                                                                                                                           | `cleanRule`, `assertValidRules`                                                                                 |
| Notas citadas viram `#<tarefa>#note-<N>`, N = posição do registro no histórico do Redmine (contando os sem nota). Ordem: tarefa, depois nota. Com duas ou mais, usa o modelo de várias notas e repete a linha com `{{noteSelecionado}}`. `{{tipoAtividadeComentario}}` = tipo desta tarefa em minúsculas. Marcar ou desmarcar nota reescreve o comentário.                    | `noteNumber`, `renderHandoffComment`, `fillTemplate`                                                            |
| Tarefas vizinhas: pai, subtarefas e o outro lado das relações, em largura, até 4 níveis quando há tipos a encontrar (destino e fechamento) ou 2 sem eles; para no nível em que todos os tipos apareceram ou após 60 leituras; as que o usuário não vê são puladas.                                                                                                            | `findNearbyIssues`, `neighbourIds`                                                                              |
| Destino: tarefas vizinhas do tipo de destino, mais próximas primeiro; com uma só, ela é escolhida. Dá para informar outra pelo número.                                                                                                                                                                                                                                        | `targetCandidates`, `useTarget`                                                                                 |
| Notas a citar: desta tarefa, das subtarefas e das irmãs de tipos cobertos pela regra (não do tipo de destino).                                                                                                                                                                                                                                                                | `noteSources`                                                                                                   |
| Fechamento: para cada tipo → situação, as tarefas conhecidas desse tipo; marcadas por padrão esta tarefa e as com notas citadas, senão a mais próxima. Uma tarefa marcada em dois passos muda só no primeiro.                                                                                                                                                                 | `defaultClosingChecks`, `useClosing`                                                                            |
| Comentário, situação, responsável, versão e anexos vão num único `PUT`, só com os campos que mudam; a tarefa é relida e o que o Redmine ignorou vira aviso. Sem comentário, anexo ou mudança, nada é enviado.                                                                                                                                                                 | `CommentAndChangeUseCase`                                                                                       |
| Horas: vazio não lança; texto que não é hora ou hora extra maior que as horas impede enviar. O lançamento vai com a data de hoje, na tarefa de origem, com o comentário "<regra> → #destino" (ou a primeira linha do trâmite). A parte extra vai também para o banco.                                                                                                         | `useHandoffHours`, `useTimeSteps`                                                                               |
| O envio é uma sequência de passos com chave; repetir pula os concluídos (nunca comenta duas vezes) e mudar uma escolha refaz o passo afetado. Fecha sozinho só quando tudo deu certo sem aviso.                                                                                                                                                                               | `useSteps`, `StepsFooter`                                                                                       |
| Horas do trâmite: com o cronômetro rodando na tarefa, vêm dele (e o cronômetro é descartado depois do passo de horas, para não lançar duas vezes). Sem ele, uma regra configurada conta desde o último trâmite do usuário (journal ou lançamento dele), senão desde a última mudança de situação, senão desde a criação; o Novo trâmite começa vazio, com a lista disponível. | `useHandoffHours` (`HandoffParts.tsx`), `hoursSinceOptions`/`defaultSince` (`domain/automation/hours-since.ts`) |
| Divisão pelo expediente (como no redmine-adapter): dentro dos períodos do dia (padrão seg–sex 8–12 e 13–18) é hora normal; o intervalo entre dois períodos de um dia útil não conta; o resto (noite, fim de semana) é hora extra. Horas = normais + extra; Hora extra = a parte extra.                                                                                        | `splitWorkTime` (`domain/time/business-hours.ts`)                                                               |
| Ícone por regra (opcional, de uma lista fixa), no botão do detalhe e no menu ⋮.                                                                                                                                                                                                                                                                                               | `HandoffRule.icon`, `ActionIcon`                                                                                |
| Ações do Claude Code: aparecem nos tipos/situações escolhidos; o prompt troca `{{tarefa}}` (#1234), `{{numeroAtividade}}` (1234, do adapter) e `{{titulo}}`. Terminal: `claude-cli://open?cwd=<pasta>&q=<prompt>`; app: `claude://code/new?q=<prompt>` e o prompt também vai para a área de transferência. Espaços viram `%20`. Modo terminal exige pasta.                    | `claude-action.ts` (`renderClaudePrompt`, `claudeActionUrl`, `assertValidClaudeActions`)                        |
| Com situação configurada, a ação do Claude pergunta "Situação: A → B", abre o Claude e só depois muda a situação; se o Claude não abrir, nada muda.                                                                                                                                                                                                                           | `useClaudeActions` (`ClaudeActions.tsx`)                                                                        |
| Regras e ações do Claude novas começam sem nome (o campo mostra um exemplo); sem nome não salvam.                                                                                                                                                                                                                                                                             | `HandoffRulesSection`, `ClaudeActionsSection`                                                                   |

## Alterar em massa

| Regra                                                                                                                                                                                           | Onde                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
